# 弹幕桥 0.1.3

将一个已打开的 B 站直播间的新文字弹幕，显示在指定 YouTube 视频播放器上。不做时间对齐，不发送弹幕到 B 站，不提供普通视频的共享弹幕服务器。

## 安装

1. 解压安装包到一个固定文件夹。
2. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
3. 打开「开发者模式」，点击「加载已解压的扩展程序」。
4. 选择包含 `manifest.json` 的 `bili-youtube-danmaku` 文件夹。
5. 安装后刷新已有的 YouTube 和 B 站直播页面。

这是本地加载版本，不是双击安装的商店版本。请保留解压文件夹。

## 使用

1. 打开 `https://live.bilibili.com/直播间号`，确保右侧聊天区已经加载，能看到新弹幕。按 B 站页面提示完成登录（如需要）。可以静音，但不要关闭这个标签页。
2. 打开 YouTube 视频或直播并开始播放。
3. 点击浏览器工具栏的「弹幕桥」图标，在两个下拉框中选择目标 YouTube 页面和来源 B 站直播间。
4. 点击「连接直播间」，再点击「发送测试弹幕」检查播放器显示。
5. 等待 B 站出现新文字弹幕。插件不会补发安装前或加载前的历史消息。

可以调节字号、透明度、滚动时长、显示区域和昵称。这些设置仅影响之后出现的新弹幕，当前弹幕保持原样继续滚动；关闭弹幕开关则立即清屏。一个 YouTube 标签页绑定一个来源；多个 YouTube 标签页可分别绑定。绑定随标签页关闭失效，浏览器重启后请重新绑定。切换 B 站房间后也需要重新绑定。

## 排查

- 测试弹幕不显示：确认正在播放视频、开关打开，刷新 YouTube 页面后再试。测试成功只说明显示链路正常，不代表已经收到 B 站消息。
- 测试能显示但真实弹幕没有：查看弹窗状态，再到 B 站检查聊天区是否实际有新文字消息。安装或更新后需要刷新 B 站页面。
- 后台运行一段时间后停止：浏览器可能休眠 B 站标签页。将该直播间加入浏览器的「始终保持活动」或内存节省排除列表，并重新激活页面。
- 全屏：支持播放器内全屏；系统画中画窗口不支持网页弹幕层。
- 热门直播：有队列和同屏上限，拥堵时会舍弃部分消息。按弹幕宽度、速度和实际高度检查间距，允许同轨安全跟随；新弹幕优先复用靠上的安全轨道，只有碰撞或追尾风险时才紧接着向下开行；低流量时不刻意分散高度。排队超过 8 秒的消息会舍弃。
- 支持文字中的已识别表情标记，以及带文字标记的图片弹幕。礼物、付费醒目留言、没有任何可读标记的图片等不保证显示。
- 本版依赖 B 站网页结构。页面改版、实验界面或聊天区不在当前文档中时，可能需要更新采集规则。

## 隐私与权限

请求 YouTube、B 站直播页面、B 站 hdslb.com 图片 CDN 访问权限和扩展存储权限。读取页面聊天文本，在本机由扩展后台转发至所绑定的 YouTube 页面；插件没有自建外部服务器，不上传或持久化弹幕内容。表情功能会向 B 站图片 CDN 请求对应图片，下载请求不携带账号凭据；不会把弹幕正文发送给 CDN。存储内容包括显示设置、表情标记与图片地址的对应关系、标签页绑定和临时采集计数。图片缓存位于扩展运行内存中，并非已打包完整离线表情库。无自动发言、账号密码读取或 Cookie 读取功能。

## 验证范围

已对 JavaScript 进行语法检查，并使用模拟扩展环境检查转发、来源校验、房间隔离、开关、解绑及新增聊天节点去重。当前交付未完成真实 Chrome/Edge 加载和在线 B 站直播端到端验证，因此属于待实播验证的首版原型。

## 文件说明

- `background.js`：标签页绑定和本机消息转发。
- `source.js`：观察 B 站聊天区新增文字消息。
- `overlay.js`：YouTube 播放器弹幕层。
- `layout.js`：按实际占用高度与运动轨迹计算位置和追尾间距。
- `popup.html / popup.css / popup.js`：设置界面。

基于 Chrome Manifest V3 内容脚本和扩展消息通信实现。文档：https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts

## 0.1.2 排列更新

取消分散选位，改用上方优先的紧凑排列。垂直间隔为 4px，按每条弹幕实际高度紧邻排布；同轨仍检查水平间隔和未来追尾。设置变更仍只影响新弹幕。

参考 B 站开源 Android 引擎的上对齐与碰撞检测思路，独立实现，并非当前 B 站网页算法的完整复刻：
https://github.com/bilibili/DanmakuFlameMaster/blob/master/DanmakuFlameMaster/src/main/java/master/flame/danmaku/danmaku/renderer/android/DanmakusRetainer.java

已模拟检查低流量同轨复用、突发消息紧邻排布、混合字号、满屏等待及设置修改不清屏，尚未完成真实直播观感验证。

## 0.1.3 表情替换

更新后在扩展管理页重新加载插件，并刷新 YouTube、B 站直播页面。新增 B 站图片 CDN 权限，浏览器如提示请允许。

1. 在 B 站直播间展开一次表情面板，停留约一秒，让插件扫描已加载的图片及其名称。切换其他表情分页可继续学习。
2. 当面板或聊天区的图片提供 `[dog]` 等可识别名称时，插件会记住对应图片地址。受不同页面结构影响，未必能识别全部表情；截图中的整套表情尚未预先下载打包。
3. 后续收到 `哈哈[dog][dog]` 时，识别到的标记将变成图片。多个连续表情及文字混排均支持。
4. 每个图片使用预留尺寸，随新弹幕字号缩放，避免加载完成后改变轨道占用。无法获取的图片保留标记占位，不显示破图。未识别的标记保留原文。

仅按准确标记替换，不根据截图猜测名称或将普通单词替换为图片。首次下载表情最多等待约 1.2 秒；网络较慢时，本条可能仍显示文字，后续消息可使用下载好的图片。表情映射会保存；图片内存缓存可能在扩展后台休眠后重建。

已用模拟页面和模拟图片响应检查：表情面板扫描、标记映射保存、重复表情、未知标记保留、CDN 地址校验、图片下载和缓存；并回归检查原有轨道及设置行为。由于当前环境无法连接 B 站图片服务器，未完成真实表情资源下载和浏览器端到端验证。
